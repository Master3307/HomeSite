# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal website (home.master3307.org) built with Vite + React 19, plus several Node backends in `server/`: the Discord "Cultbot", a Discord OAuth account API, and a Discord profile/presence API. Package manager is **pnpm** (`packageManager` is pinned; CI uses Node 22 and `--frozen-lockfile`).

## Commands

```bash
pnpm install
pnpm dev            # builds search index, then Vite dev server; proxies /api -> http://127.0.0.1:3001 (discord-profile service)
pnpm build          # sitemap -> search index -> vite build -> export FDC polls into dist/ -> create dist/404.html
pnpm preview        # vite preview on port 8081
pnpm checks         # local equivalent of CI (scripts/checks.cjs); logs to .logs/
pnpm exec oxlint .  # lint only (config: .oxlintrc.json, react + oxc plugins)

# Setup (writes .env; guides, links, skip anything)
pnpm setup:gui      # local web page (Setup + Settings tabs), first free port 4780-4799, opens the browser
pnpm setup:cli      # same in the terminal
pnpm env:example    # regenerate .env.example from config/settings.cjs (checked by pnpm checks)

# Apps (Android now, iOS later; docs/app.md): "HomeSite App" (everything but /cult) and "CultSite App" (/cult)
pnpm app:build      # the same site build (into app/www) as two Capacitor apps: signed APKs + AABs in app/build/ (-- --app home|cult | --debug | --install | --skip-web | --sync-only)
pnpm push:setup     # Web Push (VAPID) keys into .env; -- --check shows what's ready (browser / app push)

# Backends (each needs .env, see .env.example)
pnpm bot            # Discord bot (server/bot.cjs)
pnpm accounts       # Account/OAuth API (server/account-api.cjs, ACCOUNT_API_PORT, default 3002)
pnpm discord        # Discord profile/presence API (server/services/discord-profile.js, PORT, default 3001)
```

There is no test suite. Validation is `pnpm checks` (oxlint, `node --check` on every .js/.cjs/.mjs file, static bot-entry validation, build + dist checks). `pnpm checks --discord-smoke-test` additionally hits the live Discord API with credentials from `.env`.

Admin 2FA (run on the server): `pnpm 2fa:setup` (new secret into `.env` as `ADMIN_2FA_SECRET`, prints a terminal QR code and the key; `-- --force` replaces it), `pnpm 2fa:verify` (live code + countdown, any key stops), `pnpm 2fa:qr`, `pnpm 2fa:key`. `ADMIN_2FA=on` then requires a code for the admin login and critical actions (unlocking the hub, export/import, .env changes and viewing). After a correct code the same login needs no new one for `ADMIN_2FA_GRACE_MINUTES` (default 10; `checkTwoFactor(code, purpose, holders)` with `account:<session>` / `hub:<id>` holders, browser side `src/lib/twoFactorGrace.js`). Logic in `server/services/totp.cjs`.

Hub (`/hub`, see Architecture): needs `HUB_KEY` (+ a 2FA code when `ADMIN_2FA=on`; with 2FA on, the admin key + code works too). Without `HUB_KEY` it opens with the admin key (+ 2FA when on), so a fresh server is set up there; the old `/admin-settings` page is gone. The site owner (`DISCORD_USER_ID`) logged in on the site with Discord needs no key: with 2FA off that login is enough, with 2FA on only the code is asked. `HUB_TERMINAL=on` enables the server terminal.

Other scripts: `mail:test <address>` (checks the SMTP setup; `--all` sends the light/dark × English/German looks, `--preview <folder>` only writes the HTML), `bongo:import <folder>` (Bongo Cat assets from an AssetRipper export, see Bongo Cat below), `fdc:rebadge` (re-upload FDC option images to Discord with the number + emoji badge; preview by default, `--apply` / `--all`), `search:index` (rebuild `public/search-index.json`), `fdc:import` / `fdc:export` (FDC poll data), `sitemap`, `images`, `fonts:update` (self-hosted fonts: Google Sans Flex, Nunito (/card), the Material Symbols subset, and the JetBrains Mono Nerd Font for the hub console and /card), `git-sync`, `cleaner`.

## Architecture

### Frontend (`src/`)
- `main.jsx` wraps the app in `HelmetProvider` → `BrowserRouter` → `AccountSettingsProvider` → `Root`.
- `Root.jsx` renders `App` plus the global `ThemeSwitch` / `LanguageSwitch`, and runs `twemoji.parse` over the whole tree on every route/language change (emoji served from `/twemoji/svg/`). `themeSwitchHiddenPaths` controls where the theme switch is hidden (glob-style patterns, e.g. `/cult*`).
- `App.jsx` holds all routes (`react-router` v8); unknown paths render `<Error forcedCode={404} />`. `scripts/create-404.cjs` turns the `<Route path>`s into `dist/serve.json` rewrites, so `pnpm serve` (no `-s`!) answers real routes with 200 and everything else with a real 404 (`dist/404.html`). Public routes that should be indexed must also be added to the hardcoded list in `scripts/generate-sitemap.mjs`.
- `pages/` are route components; `components/cult/` contains the Cult (Discord community) features: FDC archive/polls, voting, lobby code.
- Site search: `scripts/generate-search-index.mjs` crawls the routes in `App.jsx` and the components they render, collects static `t('key')` calls and resolves them in every locale into `public/search-index.json` (gitignored, generated). Each entry is identified as `<namespace>:<key>` with its source file:line. `components/Search.jsx` (ranking in `lib/search.js`) searches it client-side; `SearchHighlight` in `Root.jsx` scrolls to and highlights the hit after navigation. Profile search is a static placeholder in `lib/search.js`. Tune excluded routes/keys and per-route keywords in the script's config section.
- `lib/i18n.js` auto-discovers translations via `import.meta.glob('../locales/*/*.json')`: each folder under `src/locales/` is a language, each JSON file a namespace. Adding a language or namespace needs no code changes. Other languages are translated through Weblate. English is bundled (the fallback); every other language is one lazy chunk (`locale-<lang>`, vite.config.js) loaded by a small i18next backend; `main.jsx` renders after `i18nReady`, so the visitor's language is there on the first paint (`react.useSuspense: false`).
- Loading and layout stability (measured with CLS on a throttled phone; keep it that way): routes are lazy via `page()` in `App.jsx`, with `PageLoading` as the Suspense fallback (fades in after 250 ms; `screen` = full height) and `preloadPage(path)`, called on link hover/focus/touch (`Root.jsx`) and for the current page in `main.jsx`. `index.html` holds a `.boot-loading` ring inside `#root` until React draws, and preloads the icon font and the Latin Google Sans Flex file. `.material-symbols-outlined` is fixed to 1em (icon names never take room before the font loads). Google Sans Flex has metric-matched fallback faces (`main.css`). Placeholders: `.skeleton` (`--round`, `--text`), e.g. the Discord card's loading state, which must keep the same children in the same order as the loaded card. Give images `width`/`height`, reserve the final size of anything that types or loads (the /card terminal renders its finished session invisibly underneath). `getCurrentAccount()` shares one request for 2 s; `whenLoggedIn(load)` skips login-only API calls for guests (no 401s in the console); `/auth/me` and `/hub/session` answer 200 with `authenticated: false`.
- `/dash` (`pages/Dash.jsx`, `components/dash/`, `lib/dashSettings.js` version 2): look settings, editable search engines (the site's own ones too), and a board of widgets (`components/dash/widgets.jsx`: clock, bookmarks, site shortcuts, search box, iframe, note, weather via open-meteo, countdown, calendar, picture, status pings, custom JSON integration, sandboxed HTML) with an in-place edit mode. Its search is the site search (`components/Search.jsx` with `web` / `people` props): web engines, site pages, and for the owner Discord people via the hub. Synced in `settings_json.dash` (plain JSON up to 80 KB, `accountPrefs.cjs`). The custom CSS editor is `components/CssSettings.jsx`.
- `/card` (`components/ProfileCard.jsx`, `styles/personal.css`): wide screens are two columns (the Discord hero stacked, facts and links in a sticky glass aside; on the right the intro as a terminal session, the toolbelt, the 3D setup), phones one column (the wrappers are `display: contents`, `order` keeps the sequence). Type is Nunito on /card (`styles/nunito.css`, self-hosted via `fonts:update`, scoped to `.me-card`); `.card.me-card` has no 3D transform (it blurred icons). The intro (`Terminal`) replays `whoami` / `cat about.txt` / `ls interests/` as in the owner's fish + Tide prompt (transient `╰─❯ cmd` lines, full two-line prompt only at the bottom, frame drawn in CSS) in the JetBrains Mono Nerd Font (`styles/nerd-font.css`; the site sets `font-family` on `*`, so mono parts need it on their children); bio/interests from `card.json` (`bio`, `interests`), plain text kept as `sr-only`. The toolbelt is squares (logo in the text colour; on hover the square tilts up, every other one the other way, the logo takes its brand colour and the straight name pops up above; the morph measures the untilted square) with a mouse on screens ≥700px, chips with logo + name on touch screens and narrower; a tool opens `ToolCard`: it morphs into a centred card (its background `.me-toolcard__bg` grows out of the chip by transform with counter-scaled corners, never an animated clip-path, which drew stripes on some GPUs; icon flies over, texts staggered; WAAPI, reversed on close, timer fallback), its background is the chip's hover tint over the page's gradient (positioned with `--at-x`/`--at-y`, not `background-attachment: fixed`, which draws in stripes while the clip-path animates); Esc, the shade or the card itself (not the link) closes it. Texts `skills.items.<icon>`, links in `TOOLBELT`. Find me descriptions slide out on hover (desktop). The presence card spans the hero (`.discord-card__body` is `display: contents`), long titles pan (`OverflowPan`).
- `/card` setup in 3D (`components/setup/`): `SetupShowcase.jsx` (container-sized: stage + side panel at ≥1000px of room, otherwise the panel under the stage; the panel lists the parts as buttons (no mousepad / SSD / Wi-Fi entries: those picks map to mouse / board / pc) with the picked part's facts and `setup.specs.<id>`; picking a part, in the list or in 3D, flies the camera to it inside the same scene (`viewer.focus(id)`), "View it on its own" shows the single model, Cables switch, hover tints the part; the Info Center window for Software with five clickable pages: About as kinfo shows it, Energy / Devices / Graphics with a dry line each, Network showing the visitor their own IP and rough place from Cloudflare's headers via `server/services/setupWeb.cjs` `GET /setup/network`, nothing stored). `builders.js` maps tab ids to builders. `desk.js`: the whole setup (oak desk, both screens, HyperX Alloy Elite RGB, Redragon M908 (a parametric shell `mousePoint`, parts set on it with `onShell`) on a SteelSeries QcK, cables routed over the rear edge into the PC's back, HyperX QuadCast, the PC on its stand). `models.js`: every part from its real size and the owner's photos (1 unit = 1 cm; shapes cut into an extrude must stay inside its outline or the hole isn't cut): CPU, GPU (built lying down, bracket at +x, `s` = cm from the bracket, `GPU_SIDE` / `BACKPLATE` in textures.js), RAM, board, SSD, Wi-Fi card, the monitors (LG 22MP55 class, Samsung S22D300HY), the case (`buildCase`, cube perforations as alpha maps), the tower cooler and RGB fans, `buildPc` (parts carry `userData.pick`, `hotspots`, `setOption('cables')`). `scene.js`: the viewer (product-shot light mixed by the theme's progress, so it follows the theme switch; drag to turn, right-drag / two fingers to pan within a radius, pinch or Ctrl + wheel to zoom; picking, `focus(id)` (bounds of everything with that pick, `userData.frame === false` excluded), hover tint; draws only while visible). `textures.js`: canvas-drawn prints, panels, the desktop on the screens. three.js (pinned) loads as its own chunk only when the section comes near. Parts and facts: `SETUP` / `SOFTWARE` in `src/data/links.js`, texts in `card.json` (`setup.*`).
- Frontend config: settings with `public: true` in `config/settings.cjs` are injected by `vite.config.js` and read via `src/lib/siteConfig.js` (needs a rebuild after changes). Never hardcode IDs, domains or URLs.
- HomeSite logo and icon: the sources are `public/img/HomeSiteLogo.svg` / `HomeSiteIcon.svg` (static) and `*Animated.svg` (intro played once; `*Animated.webp` are raster copies that play once). Every other HomeSite icon is rendered from them: `favicon.svg` (= HomeSiteIcon.svg), `favicon.ico` / `-16/32/48.png`, `favicon.png/.webp`, `img/HomeSiteIcon.png/.webp`, `img/HomeSiteLogo.png/.webp` (3x); the app icons (`apple-touch-icon*`, `android-chrome-*` incl. `-maskable-*`, `mstile-*`, `AppNoTransparent.png`, `img/AppIcon.png`) are the purple square with the H in the middle; `img/GitHubCard.png` is the social card. `index.html` links the favicons, apple-touch icon, `site.webmanifest` and `browserconfig.xml`. Page titles come from the `title` locales as whole phrases ("Card of HomeSite", "HomeSite of MrKoby07"); `PageTitle` in `components/SiteLogo.jsx` draws the word HomeSite as the logo (a link home) and MrKoby07 bold, so every language places them itself. `SiteLogo` is also in the hub (house icon); static under reduced motion. The `hehehe/` icons are the cult's own, not HomeSite's.
- Icons: Material Symbols are self-hosted as a subset font. Icon names used dynamically (`<Icon name={…} />`, `icon: '…'`) must be listed in `scripts/material-symbols.extra.json`, then run `pnpm fonts:update`.

### Apps (`app/`, `src/lib/native.js`, docs/app.md)
- Capacitor 8, two Gradle flavors from one site build: `home` (HomeSite App, `APP_ID`/`APP_NAME`: every page except /cult) and `cult` (CultSite App, `CULT_APP_ID`/`CULT_APP_NAME`: /cult, starts there). Shared in both: `/cult/settings|notifications|privacy`, `/license`, `/error` (`SHARED_PAGES`/`pageOwner` in native.js, mirrored by the App Link paths in `app/android/app/src/<flavor>/AndroidManifest.xml`); in the HomeSite app `CultShell` wears HomeSite's look. Links to the other app's pages go through `HomeSitePlugin.openUrl` (the other app if installed, else the browser): a capture-phase click handler before React Router, `openInApp`, and a `pushState` guard. Branding per flavor in `src/<flavor>/res` (icons are vectors: HomeSiteIcon.svg / the traced server cat, sources + 512px store icons in `app/branding/`). Each app logs in separately (separate cookie stores).
- `pnpm app:build` (`scripts/app-build.mjs`) runs the normal `pnpm build` with `BUILD_OUT_DIR=app/www` (vite, export-fdc, create-404 and app-links honour it, so the web's `dist/` is untouched), writes `capacitor.config.json`, `app/android/homesite.properties` and each flavor's `assets/public/index.html` with `<meta name="homesite-app" content="home|cult" data-id="<package>">` (all generated, gitignored), `cap sync`, then Gradle. JDK 21 + Android SDK from `JAVA_HOME`/`ANDROID_HOME` or `~/Android/jdk-21` + `~/Android/Sdk`. Release key made once in `app/keys/` (gitignored, must be backed up; backups include it and `app/google-services.json`, nothing else under `app/`: `APP_KEPT` in backup.cjs); its SHA-256 goes into `APP_CERT_FINGERPRINTS`, which `scripts/app-links.cjs` (end of `pnpm build`) publishes as `/.well-known/assetlinks.json` for both packages (`APP_TEAM_ID` → `apple-app-site-association`).
- The apps serve the bundle under the site's own host (`server.hostname` = FRONTEND_ORIGIN's host, `androidScheme: https`), so cookies (same-site with the API subdomains), CORS, CSRF, passkeys and the hub WebSocket work unchanged. Capacitor only intercepts that host; requests there without a file and without a dot in the last segment get index.html, so never navigate the whole page to a dotted path inside the app (use `openInApp`).
- `src/lib/native.js` (only when `Capacitor.isNativePlatform()`; `appBrand` is null on the web): Discord login in the system browser (`/auth/discord?app=<PKCE challenge>&scheme=<package>` → one-time code to `<package>://login` → `POST /auth/app/exchange`, in `discordOAuth.cjs`, schemes = `APP_ID`/`CULT_APP_ID`), other sites in a Custom Tab, App Links / notification taps inside the app, `a[download]` and blob downloads through `HomeSitePlugin.saveFile` (Android's Save-as; share sheet fallback), the back button (closes `[role=dialog]` with Escape first, then `history.back()` while React Router's `history.state.idx > 0`, else minimise), the splash, and the system bar colours (`HomeSitePlugin.setBars`, top `--bg-secondary`, bottom `--bg-primary`). Native code: `app/android/app/src/main/java/org/homesite/app/` (`MainActivity`: edge-to-edge after `super.onCreate`, WebAuthn for the app; `HomeSitePlugin`: `info`, `setBars`, `openUrl`, `saveFile`).
- Push: `server/services/push.cjs` (account API; `push_devices` table, Web Push via `web-push` with `WEB_PUSH_*`, FCM HTTP v1 with `FCM_SERVICE_ACCOUNT`, routes `/push/config|devices|test`), called from `moderation.cjs` `notify()` when `settings.notify.<category>.push !== false`. Client `src/lib/push.js` (web: `public/push-sw.js`, only push + click, no caching; apps: `@capacitor/push-notifications`, one Android channel per category), UI `components/cult/PushSettings.jsx` in Settings → Notifications. The apps have push only when `app/google-services.json` (listing both packages) exists at build time (`BuildConfig.HAS_PUSH`). Logging out removes the device.

### Backends (`server/`, mostly CommonJS `.cjs`)
- **Discord bot** (`bot.cjs`, based on NamVr's DiscordBot-Template): dynamically loads handlers from `events/`, `commands/<category>/` (legacy prefix commands), and `interactions/{slash,buttons,select-menus,context-menus,modals,autocomplete}/<category>/`. Adding a command means dropping a file in the right folder; follow the shape of existing files. Types live in `server/typings.d.ts`. CI statically checks that `bot.cjs` still references `DISCORD_BOT_TOKEN`, `DISCORD_CLIENT_ID` and `client.login(token)`.
- **Account API** (`account-api.cjs` + `services/discordOAuth.cjs`): Express on 127.0.0.1, Discord OAuth login, SQLite (`better-sqlite3`, `accounts.sqlite`), cached avatars. A reverse proxy routes public `/auth/*` and `/avatars/*` here.
- **Discord profile API** (`services/discord-profile.js` + `services/discord-profile/`): ESM Express service for presence/activity tracking, enrichment (RAWG/IGDB/SteamGridDB/Spotify), and the live-user routes. Public: `/`, `/health`, `/api/discord-profile/avatar` and `/<DISCORD_USER_ID>` (the home page card). Everything else that exposes people (`/<id>`, `/<id>-ui`, `/history`) needs the hub key or a hub login (`discord-profile/hub-auth.js`). This is the `/api` target in dev (`/profile-api` is the same without the prefix, for the `-ui` pages).
- **Hub** (`/hub`, `src/pages/Hub.jsx` + `src/components/hub/`; backend `services/hub.cjs` on the account API): overview/health/stats, member list + ranked search, live activity feed (SSE), running bot commands (`services/hubCommands.cjs` builds a stand-in interaction/message), logs (`services/hubLogs.cjs`), database/users/data files (`services/hubDb.cjs`), the settings workspace and a server terminal (`services/hubTerminal.cjs` + `pty-helper.py`, WebSocket with HTTP fallback, sessions resume after dropped connections and survive the account API being stopped/restarted (with python3 `pty-helper.py --serve` detaches each shell and serves it on a Unix socket in `db/hub-terminal/` (0700, not backed up), keeping the last 4 MB of output (the account API keeps 4 MB per session for reloads, and the console stays mounted across hub tabs); on start the API reattaches them under the same id via `restoreSessions`; keys typed while the API is down are queued in the browser and sent in order; an unattached shell ends after 12 h; under systemd the account API's unit needs `KillMode=process`, or a `systemctl restart` still ends them); `components/hub/Console.jsx` handles touch itself: one-finger scroll with momentum, also inside full-screen programs, pinch for the text size, a typing field that sends each change live as a diff so phone keyboards' suggestions/autocorrect work, full screen sized to `visualViewport` above the on-screen keyboard, a text view for selecting output; tabs can be dragged into another order (mouse / pen), renamed by double click, closed with the middle button, and have a right-click menu (`components/hub/ContextMenu.jsx`; long press on touch); order and names in localStorage `hub.terminal.order` / `.names`; a dot marks a background tab with new output, an amber one a bell; the terminal's own menu (right click or long press; Shift + right click gives the browser's): copy, paste, select all, find (Ctrl+Shift+F, `FindBar`), show as text, save the output as a .txt, text size (also Ctrl + wheel), top / end, clear, interrupt, close). Discord data comes from the bot's internal API (`services/hubBot.cjs`, `/hub/*` routes); the bot records every activity change for the Live tab in `db/hub-live.jsonl` (last 2000 events, max 7 days, not backed up). Login: `HUB_KEY` + 2FA → `__Secure-homesite_hub` cookie (parent domain, so the profile API's `-ui` pages accept it via `GET /hub/session`); sessions live in `db/hub-sessions.json` (not backed up). The code is public: keep every hub route behind `requireHub`, every mutation behind the Origin/CSRF check (`requireTrustedMutation`), log writes to the activity log, never send secrets to the browser.
- Shared server helpers: `services/http.cjs` (`httpError(status, message, extra)`); the route wrappers stay per service (they differ on purpose).
- **Service logs:** every service calls `services/processLog.cjs` `capture(name)` first, which copies its console output to `.logs/services/<name>.log` (rotated at 5 MB). New services should do the same so `/hub` → Logs shows them.
- **Bongo Cat** (lobby cat, cat designer, designed FDC options): the game's textures from the owner's own copy, ripped with AssetRipper and imported via `pnpm bongo:import`, the setup stage "bongo", or the folder upload in the hub (`/hub/settings/bongo`). `shared/bongo-assets.mjs` holds the import rules (used by the browser upload and the server, no fixed item/theme lists: new items, slots, UI themes and `Icon_*` icons of a game update are picked up by importing again; slots the site draws are `SLOT_FILES`). `services/bongoAssets.cjs` installs atomically into `db/bongo-cat/` (`textures/`, `catalog.json` with items, aliases, layer bounds, UI themes cut from the `sactx-*` sheets into `ui-<theme>-<Piece>.png` plus a colour palette per theme that the site's own layout is drawn in, the game's fonts from `Assets/Font` (`catalog.fonts`; Nunito and Noto Sans are used as "Bongo Nunito" / "Bongo Noto Sans" in the Bongo UI and on /cult once imported), hashes, history); updates only replace changed files and keep retired items. `shared/bongo-design.mjs` is the layer stack (part offsets taken from the game's scene: bongos lower and in front, hat above; cats face right, `flip` mirrors) + the FDC design layout (`{ cats: [...] }`, 1-4 cats, every slot combination a GIF frame), shared by the browser preview and `services/bongoRender.cjs` (PNG/GIF). Search words: curated single words in `shared/bongo-aliases.json` (baked in at import and joined again when the catalog is served), plus words FDC editors add in the picker (right-click) in `db/bongo-aliases.json` (backed up, merged on import; edits are queued so quick changes don't overwrite each other). Routes in `services/bongoWeb.cjs` (catalog, textures, per-user favourites + UI theme in `db/bongo-favorites.json`, lobby wardrobe, admin import); lobby style/wardrobe/winner logic in `services/lobbyStyle.cjs` (`db/lobby-cat-style.json`). Without imported assets the lobby cat is hidden and FDC options need an image; with them every new option needs a design (`option.design`, `option.display`, file `<n>-design.png|gif`).
- **Stats** (`/cult/stats`, FDC editors only, in the account menu): `services/statsWeb.cjs` (registered by fdcWeb, `canCreateFdc`) with `/stats/access`, `/stats/migration`, `/stats/lobby` (`?from&to` UTC days); page `src/pages/CultStats.jsx` (sortable tables, rankings, per-day columns, `stats` locale namespace, not in the search index). Migration events come from `<archive>/recycling-bin/migration-log.jsonl` (`fdcMigration.cjs` `record`: migrate / redesign / suggest / approve / reject, `via` direct | suggestion | manage; designs made before the log existed are backfilled once; the manage view's designs are logged through `recordManage`; account deletion takes names out). Lobby cat per day: table `lobby_daily` (per member, merged by MAX in backups) and `site_counters` keys `taps-day:<day>:guests|members` / `pets-day:…`. Private profiles are counted but never named.
- **Members & privacy** (`/cult/user/:key` with `@username` | Discord ID | account id, `/cult/settings`, `/cult/members`, `/cult/privacy`): `services/members.cjs` (account API: profiles, public/private, bongo avatars + uploaded background picture/GIF, per-user presets, member list, reports into the review channel, nickname changes via the bot, lobby cat taps, deleting an account + the daily cleanup of people who left `ACCOUNT_INACTIVE_DAYS` ago) and `services/memberData.cjs` (bot, internal API `/members/*`, `/privacy/forget`: Discord data for profiles, presence, reports, nickname, erasing a user from the bot's data + its messages that mention them). `services/privacy.cjs` is the shared `db/privacy.json` (private profiles never shown online, deleted accounts hidden from every lookup for 13 days, salted hashes so a restored backup can't bring them back; backup.cjs skips/scrubs them). Deleting rewrites the activity log once (`activity.forget`), leaving a single "deleted their account" entry. Login is members-only (`MEMBERS_ONLY_LOGIN`). Bongo avatars: `shared/bongo-avatar.mjs` (free layers, snap, rotate) rendered by `bongoRender.renderAvatar`. Settings sync in `users.settings_json` (`services/accountPrefs.cjs`, client `src/lib/prefs.js` + `accountSettings.jsx`). **Keep `src/pages/CultPrivacy.jsx` in sync with what is stored.**
- **Hub settings (formerly /admin-settings):** `/hub/settings/<section>` (overview, one per settings section, custom, `backup`, `bongo`; the section is in the address). `/admin-settings[/<section>]` and `/backup` redirect there. Backup routes (`adminBackup.cjs`) only accept an unlocked hub session (`hubSessionOf`), which counts before any website login; its 2FA grace (`hub:<id>` + `account:<session>`) carries over, exporting/importing still needs the admin key (it encrypts).
- **Profile answers & birthdays:** the onboarding roles (`PROFILE_ROLE_ID`, `PROFILE_GENDER_ROLES`, `PROFILE_HOBBY_ROLES`) move into the site profile for everyone with an account: the bot (`services/profileRoles.cjs`) watches role changes, sweeps every 10 minutes and runs on account creation, posts to `POST /internal/profile-roles` (members.cjs) and removes the roles. Options in `shared/profile-options.json`, UI `src/components/cult/AboutMe.jsx`. Birthdays: `services/birthday.cjs` is the shared store (bot `/birthday` and the site), with `setAt` (first saved = priority when two celebrations fall on one day; the later one moves a day, `celebrations(year)`), `changedAt` (one change per 6 months, `CHANGE_LOCK_MS`) and the birthday person's `dressCode`. Website routes in `services/birthdaysWeb.cjs` (`/cult/birthdays`, profile line, `/cult` banner, the lobby cat wears the dress code: `lobbyStyle.cjs` order temporary > birthday > FDC winner > mode). The birthday dress code is picked on the celebration day itself (`dressCode.for`, `currentDressCode`), cleared the day after. The list shows logged-in members everyone with a birthday (no account: Discord name + user card, `members.discordUsers`). Reminders `services/birthdayReminders.cjs` (`db/birthday-reminders.json`, DMs from `birthdayCelebrations.cjs` the day before and on the day); dress code pictures in `db/birthday-dress/`.
- **FDC migration:** new options are designed cats only (the "Image + cat" mode is gone; without imported assets options stay pictures). Recycling-bin items carry a design (`item.design`, rendered into `recycling-bin/designs/`); picture-only items show a red "!" and are designed next to their old picture (`DesignEditor` `reference`). `?fdc=migrate` (`FdcMigration.jsx`, `services/fdcMigration.cjs`) covers every option with a picture but no design: archived and running poll options (`p.<date>.<n>`, saved through the bot's `setDesigns`, the option then shows the design and keeps its picture) and bin items whose FDC is gone (`b.<id>`); a bin copy of an archived option is designed together with it. Editors design directly, members suggest (`recycling-bin/suggestions.json`), editors approve / adjust / reject; the button disappears when nothing is left. With the Bongo Cat assets imported, pictures are retired everywhere (create, manage, past FDCs by hand): fdcWeb rejects new / changed images, removing a design or switching back to the picture; editors see a small red "!" on picture-only options and FDCs and migrate them in the manage view (old picture faded behind the slot, side by side in the designer). Design model (version 3, `shared/bongo-design.mjs`): per cat `skins/hats/bongos` picks mixed by `combine` (all | paired), fixed looks `outfits` that never mix, `link` (changes in step with the cat before it); `mix` across cats each | together | all | shuffle (version 2 designs keep "all"), `frameMs`, `tap` ({ on, ms }).
- **Email look** (`services/mailTemplate.cjs`): every email is a tiny cult page in the member's language (`src/locales/<lang>/email.json`), theme (light / dark / system → the mail app's mode) and custom CSS, in /cult's exact colours: the site's page gradient, its card (the Discord server card's fill, border, corners, shadow) with the server icon tile in its head (`public/hehehe/<season>-icon.png`, inline), cult red; every gradient / transparent colour sits on a solid fallback for Outlook (the icon follows `shared/seasons.json`, sent as cid). Notifications carry `List-Unsubscribe` + one-click (`services/emailUnsubscribe.cjs`, signed links, exempt from the CSRF check); security emails (new browser, password/2FA changes) always go out with a reset link (`/cult?login=reset&email=`).
- **Email login & 2FA** (`services/emailAuth.cjs`, `services/mail.cjs`): accounts are only created with Discord; a verified email + password is an extra way in, with optional second factors (email code, authenticator app, passkeys via SimpleWebAuthn). Needs the `SMTP_*` settings (`pnpm mail:test you@example.com`). Discord logins never ask for these factors; "Trust this browser" skips the second step for 30 days (`__Secure-homesite_trust`, MAC over the password hash + methods). Codes are HMACs, TOTP secrets AES-GCM sealed with the internal key; the hub DB view masks credential columns.
- Other `services/` modules (levels, birthday wishes, petting, sticky messages, Minecraft status, FDC archive, DM forwarder) are used by the bot.
- Runtime data is stored in `server/services/db/` (gitignored). FDC poll data in `server/services/db/fdc-polls` is exported to `public/fdc-polls` (dev) or `dist/fdc-polls` (build) by `scripts/export-fdc.cjs`.

### Deployment
`scripts/deploy.sh` runs on the server (`/opt/homesite-api`): hard-reset to `origin/master`, `pnpm install --frozen-lockfile`, `pnpm checks`, `pnpm build`, then restart the systemd units `homesite`, `accounts-api`, `discord-bot`, `discord-profile`. It is triggered by `server/services/github-deploy-listener.mjs`. So `master` is production; day-to-day work happens on `dev`.

### Backups (keep up to date!)
`server/services/backup.cjs` (the hub's settings, `/hub/settings/backup`; `/backup` redirects there; routes in `server/services/adminBackup.cjs`) exports everything git doesn't track — `server/services/db/` (accounts SQLite, FDC archive, recycling bin, activity log, bot data), avatars, logs, `.env` — as one encrypted archive and imports it again (merge or restore).
- **Any change to runtime data must be checked against the backup immediately:** new files or folders written at runtime, new SQLite tables/columns, renamed paths or changed JSON/CSV formats. Make sure they are included (or deliberately listed in `EXCLUDED`), and that imports merge them correctly (`MERGERS` for files with per-user data such as points, levels, birthdays; `mergeAccounts` for the database).
- Compatibility both ways: an old backup must import into new code and a new backup into old code (column intersection, tolerant JSON readers, `manifest.version`).

### Settings / environment variables (keep up to date!)
`config/settings.cjs` is the single source of truth for every .env setting (section, feature, label, description, type, importance, `needed`, default, `public`, `applies`, help links). It drives `.env.example` (`pnpm env:example`), the hub's Settings tab, `pnpm setup:gui` / `setup:cli` (stages in `scripts/setup/stages.cjs`) and runtime defaults (`server/config.cjs`: `setting`, `ids`, `number`, `enabled`, `origin`).
Whenever a setting is added, renamed, removed or changes meaning:
- Add/update it in `config/settings.cjs`, run `pnpm env:example`, and add it to a setup stage if a newcomer should be asked about it.
- Read it through `server/config.cjs` / `siteConfig`, never `process.env` with a personal hardcoded fallback. Empty optional values must switch that feature off cleanly, not crash.
- Owner-specific values (IDs, domains) belong in the local `.env`, not in code or `.env.example`.
